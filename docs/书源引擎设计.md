# 书源引擎设计

参考 [HapeLee/legado-with-MD3](https://github.com/HapeLee/legado-with-MD3) 的核心设计：
**程序本体只负责调度、UI、缓存、书架、任务队列；每个站点怎么抓、怎么解析，全部放在独立的「书源」配置里。**

目标不是再写一个「某小说网下载器」，而是把 legado 的小说书源体系搬到桌面端：

- 书源是 JSON，可导入、导出、编辑、启用/停用；
- 规则语法尽量复刻 legado，现有小说书源改改就能用；
- 网络、JS、解析、分页、缓存各自分层，互不污染；
- 换站点只改配置，不改程序。

## 1. 技术选型

| 层 | legado（Android） | 桌面版（本项目） | 说明 |
|---|---|---|---|
| UI | Compose / View | Python Tkinter | 复用「小工作箱」，不额外引入桌面框架 |
| 网络 | OkHttp + Cronet | `urllib` 封装（`book_source/http.py`） | 统一 Cookie、代理、超时、重试、编码、gzip/br、限速 |
| HTML 解析 | jsoup + JsoupXpath | `lxml` + `cssselect` | 真实 HTML 容错解析、真实 XPath 1.0、CSS 选择器 |
| JSON | JsonPath | `jsonpath-ng` | 支持 `$..`、`[*]`、过滤表达式 |
| JS 引擎 | Rhino | **SpiderMonkey（pythonmonkey）** | 语法覆盖更全；Python 函数可同步注入 JS，`java.ajax` 行为接近 Rhino |
| 规则 DSL | `AnalyzeRule` | `book_source/rules.py` | 复刻默认规则、`@CSS:`、`@XPath:`、`@Json:`、`@js:`、`##`、`&&/||/%%` |
| 存储 | Room | JSON 文件（`%APPDATA%\小工作箱\书源`） | 书源、书架、章节缓存、阅读设置 |

为什么不用纯 Python 手写 JS 解释器：书源里的 JS 会用到闭包、原型、正则、`JSON`、
`java.ajax` 等，自己实现一个子集既慢又容易在真实书源上翻车。SpiderMonkey 是真正的
ES 引擎；`pythonmonkey` 允许把 Python 可调用对象直接放进 JS 作用域，所以
`java.ajax(...)` 可以同步走本项目的网络层。

为什么不用 Node/Java 子进程：单进程更简单，Tkinter 与引擎共享内存数据；不需要
额外打包 Node/JRE，也不需要写 JSON-RPC。

## 2. 模块划分

```text
book_source/
├── http.py        网络请求层：请求头、Cookie、代理、超时、重试、编码、解压、限速
├── js.py          JS 引擎：SpiderMonkey + 单线程求值队列 + 宿主桥
├── dom.py         HTML/XML/JSON 解析：lxml、cssselect、jsonpath-ng、正文清洗
├── rules.py       规则解析引擎：legado DSL、@put/@get、{{}}、JS 规则
├── source.py      书源模型：legado JSON 字段、校验、导入/导出、去重
├── engine.py      业务编排：搜索、详情、目录、正文、发现、URL 模板、分页
├── store.py       本地存储：书源、书架、章节缓存、阅读设置
├── tasks.py       任务队列：固定工作线程、取消、事件
├── ui.py          Tkinter 页面：搜索、书架、目录、阅读、书源管理
├── demo_site.py   内置示例站点（测试 + 演示，不访问外网）
└── models.py      纯数据：SearchBook / BookInfo / Chapter / BookContent / BookshelfItem
```

依赖方向：

```text
ui → tasks / store / engine → rules / source / models
engine → http / js / dom
rules → dom / js / http / models / source
```

`ui` 不直接发 HTTP，`engine` 不碰 Tk，`rules` 不认识具体网站。

## 3. 书源 JSON

字段与 legado 小说书源保持一致（未列出的字段会原样保留在 `raw` 中）：

```json
{
  "bookSourceName": "站点名",
  "bookSourceUrl": "https://example.com",
  "bookSourceGroup": "分组",
  "bookSourceType": 0,
  "enabled": true,
  "enabledExplore": false,
  "header": "{\"User-Agent\":\"...\"}",
  "searchUrl": "/search?q={{key}}&page={{page}}",
  "exploreUrl": "分类::/list/1.html\n排行::/top.html",
  "bookUrlPattern": "/book/\\d+",
  "ruleSearch": {
    "bookList": "class.book-list@tag.li",
    "name": "class.title@text",
    "author": "class.author@text",
    "bookUrl": "tag.a@href",
    "coverUrl": "tag.img@src",
    "intro": "class.intro@text",
    "lastChapter": "class.latest@text"
  },
  "ruleBookInfo": {
    "name": "id.info@tag.h1@text",
    "author": "id.info@tag.span.author@text",
    "intro": "id.intro@text",
    "coverUrl": "id.info@tag.img@src",
    "tocUrl": "id.toc@href"
  },
  "ruleToc": {
    "chapterList": "id.list@tag.dd",
    "chapterName": "tag.a@text",
    "chapterUrl": "tag.a@href",
    "nextTocUrl": "id.next@href"
  },
  "ruleContent": {
    "content": "id.content@html",
    "nextContentUrl": "id.next-page@href",
    "replaceRegex": "##广告##"
  }
}
```

`bookSourceUrl` 是书源唯一键；同一域名要拆成多个书源时，用不同路径作为唯一键
（内置示例就是这样：`/html`、`/json`、`/regex`）。

## 4. 规则 DSL

### 4.1 默认规则

`规则片段@规则片段@...`，片段之间用 `@` 分隔：

- `class.xxx`：class 包含 xxx 的后代元素；
- `id.xxx`：id 等于 xxx 的后代元素；
- `tag.xxx`：标签为 xxx 的后代元素；
- `text.xxx`：直接文本包含 xxx 的后代元素；
- `children` / `parent` / `sibling` / `prev`；
- CSS 选择器：其他写法直接交给 `cssselect`；
- 索引：`tag.a.0`、`tag.a.-1`、`tag.a[0]`、排除写法 `p!0`；
- 末段取值：`text`、`textNodes`、`ownText`、`html`（outerHTML）、`all`、
  标签名（如 `@a`）、或任意属性名（`href`、`src`、`data-id`…）。

示例：

```text
class.book-list@tag.li@tag.a@text
id.content@html
tag.a@href
class.item.-1@tag.a@href
```

### 4.2 规则类型前缀

| 前缀 | 说明 |
|---|---|
| `@CSS:` | CSS 选择器，`选择器@text` 取文本 |
| `@XPath:` 或 `/` 开头 | XPath 1.0，支持 `//div[@class="x"]/a/@href` |
| `@Json:` 或 `$.` / `$[` 开头 | JSONPath；内容本身是 JSON 时可省略前缀 |
| `@js:` | 执行 JS，`result` 为上一段规则结果 |
| `<js>...</js>` | 内联 JS 段，可夹在规则中间 |
| `:` 开头（仅列表规则） | 正则列表，字段用 `$1`、`$2` 取分组 |
| `@@` | 强制按默认规则解析 |

### 4.3 组合与修饰

- `a||b`：取第一个非空结果；
- `a&&b`：连接两个结果；
- `a%%b`：按索引交错（legado 的列表合并语义）；
- `规则##正则##替换`：正则替换；写成 `规则##正则##替换###` 只替换第一个匹配；
- 规则前加 `-`：反转列表（常用于 `bookList` / `chapterList`）；
- `@put:{key: 取值规则}`：把值写入变量（书籍/章节变量）；
- `@get:{key}`：读取变量；
- `{{表达式}}`：在 URL 或规则里嵌入 JS/变量，如 `{{key}}`、`{{page}}`；
- `$1`：正则列表分组，或列表结果的下标占位。

### 4.4 URL 模板

`searchUrl` / `exploreUrl` / `nextTocUrl` 支持：

- `{{key}}`、`{{page}}`、`{{book}}` 等 JS 表达式；
- `<1,2,3>` 页码选择：第 1 页取 1，超出取最后一个；
- `,{...}` 请求选项（legado 语法）：

```json
"/search?q={{key}},{\"method\":\"POST\",\"body\":\"q={{key}}\",\"charset\":\"gbk\",\"retry\":2}"
```

支持 `method`、`headers`、`body`、`charset`、`retry`、`js`。查询参数会自动做
URL 编码，已经编码过的参数不会二次编码。

## 5. 网络层

`book_source/http.py`：

- 每个书源独立 `CookieJar`，`get_cookie` / `set_cookie` 可给 JS 用；
- 请求头合并：默认 UA → 书源 `header` → 单次请求头；
- 代理：显式 `proxy` 或系统环境变量；
- 超时、重试（408/425/429/5xx），指数退避；
- 编码识别：BOM → Content-Type charset → `<meta charset>` → UTF-8 → GB18030；
- `gzip` / `deflate` 必选，`br` 在安装 `brotli` 时启用；
- 按域名限速：`concurrentRate`（`2/1000` 表示每秒 2 次；`500` 表示间隔 500ms）；
- 书源规则里写死了旧域名/镜像域名时，连接被拒绝会自动改用书源自身域名重试一次；
- 部分站点会 reset 普通 GET，此时自动改用无 body 的 POST 重试（再失败才报错）；
- 可选磁盘缓存接口（`ResponseCache`）。

## 6. JS 引擎与宿主桥

`book_source/js.py` 用 `pythonmonkey` 执行 SpiderMonkey：

- 所有求值进入**单独的 JS 线程**，调用线程同步等待，避免 SpiderMonkey 跨线程问题；
- 书源的 `jsLib` 会在每次求值前注入，`towan()` 这类公共函数可直接使用；
- JS 作用域注入：`result`、`baseUrl`、`book`、`chapter`、`source`、`cookie`、
  `cache`、`key`、`page`、`title`、`src`、`nextChapterUrl`、`java`、`Packages`；
- `source` 提供 `getKey/getTag/get/put/getVariable/putVariable` 等 legado 常用方法，
  `cookie` 提供 `getCookie/setCookie/removeCookie/getKey`，`cache` 提供 `get/put/delete`；
- 只实现了 `Packages.java.lang.Thread.sleep` 和 `System.currentTimeMillis` 两个 JVM 桩，
  其它 `Packages.*` 不可用；
- `java.*` 同步桥：`ajax`、`ajaxAll`、`connect`、`get`、`post`、`base64Encode/Decode`、
  `md5Encode`、`hexEncodeToString`、`timeFormat`、`encodeURI`、`htmlFormat`、
  `getCookie`、`put` / `get`、`log` 等；
- 未安装 `pythonmonkey` 时只有 `@js:` 规则不可用，其它规则照常。

未实现：`webView`（真实浏览器渲染）、`Packages.cn.hutool.*`（JVM 专有类）、
`queryTTF`（字体解密）、TTS/音频。

## 7. 业务流

### 搜索

1. `searchUrl` + `{{key}}/{{page}}` 生成请求；
2. `bookList` 得到元素/JSON 对象列表；
3. 逐项取 `name/author/bookUrl/...`；
4. `bookUrl` 为空时回退当前页；`bookUrlPattern` 命中当前页时按详情页解析；
5. 同地址去重，`-` 前缀反转。

### 详情

`init` 可先缩小解析范围；取书名、作者、分类、字数、最新章节、简介、封面、
`tocUrl`（为空回退书籍地址）。

### 发现

`exploreUrl` 支持三种写法：`名称::地址` 多行、JSON 数组、`@js:` 返回
`[{title, url}]` 数组（可用 `{{page}}` 占位）。界面「发现」按钮会列出分类/榜单。

### 目录

`chapterList` 逐项取章节名/地址/卷/VIP；`nextTocUrl` 支持单页循环和多页并发
（桌面版串行，最多 12 页）；`-` 前缀反转；`formatJs` 可逐章改标题。

### 正文

`content` 取正文；`nextContentUrl` 自动翻页（最多 20 页），遇到下一章地址停止；
`replaceRegex` 全文替换；最后把 HTML 清洗成纯文本（保留段落换行）。

## 8. 存储与任务

```text
%APPDATA%\小工作箱\书源\
├── sources.json     书源
├── bookshelf.json   书架 + 目录 + 进度
├── cache\<book>\    章节正文缓存
└── settings.json    字号、行距、最近书源
```

`tasks.TaskQueue` 固定 4 个工作线程，UI 用 `after` 轮询事件；搜索、详情、目录、
正文、缓存全本都在后台线程执行，Tk 主线程只更新控件。

## 9. 已知边界

- 不做浏览器渲染：需要 WebView 执行 JS 才出内容的站点不支持；
- 不做登录/验证码交互：只支持 Cookie 与 `header`；
- 未实现 `loginCheckJs`、`coverDecodeJs`、`webJs`、`subContent`、
  `sourceRegex` 等 legado 扩展字段；
- 书源支持本地文件、链接、剪贴板导入；
- `bookSourceType` 只实现文本（0），音频/图片/文件下载未实现；
- 源站目录本身缺章时无法凭空补齐；界面会提示缺章编号，换有完整目录的书源即可；
- 书源是可执行配置（JS），只应导入可信来源；
- `pythonmonkey`、`lxml`、`cssselect`、`jsonpath-ng` 是可选依赖，缺失时书源阅读页
  会显示安装提示，其它工具不受影响。

## 10. 验证

```powershell
python -m unittest -v test_book_source.py
```

覆盖：默认规则、CSS、XPath、JSONPath、正则列表、`&&/||/##/@put/@get`、JS +
`java.ajax`、GBK、gzip、目录分页、正文分页、书架、缓存、书源导入导出。

内置示例站点（`book_source/demo_site.py`）提供 HTML、JSON、正则、GBK、gzip 页面；
界面上的「示例站点」按钮会启动它并导入三个示例书源。
